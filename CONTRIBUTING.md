# Contributing

We welcome focused contributions from authorization, identity, e-signature, legal-tech, passkey, security, and developer-tooling practitioners.

## Good first contributions

- review the document profile and threat assumptions;
- add a provider adapter behind a mock or sandbox;
- improve cross-SDK conformance fixtures;
- add jurisdiction notes clearly marked as non-legal advice;
- improve verifier diagnostics without weakening validation.

## Workflow

1. Open an issue describing the use case and acceptance evidence.
2. Keep changes narrow and avoid modifying APOA semantics inside this repository.
3. Add or update tests for normative behavior.
4. State security, privacy, compatibility, and legal assumptions explicitly.
5. Use Conventional Commits where practical.

Generic APOA improvements should be proposed upstream first. Candao-specific document semantics belong in this profile.
