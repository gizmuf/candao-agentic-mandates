# Codex for Open Source readiness

OpenAI's program evaluates active open-source maintainers using signals such as meaningful usage, broad adoption or clear ecosystem importance, and evidence of ongoing maintenance.

This project may eventually have a credible ecosystem-importance argument because it targets interoperable authorization evidence for agent execution. Compatibility with APOA is a positive signal if the project contributes a distinct profile, tests, integrations, and upstream improvements; merely repackaging APOA would be weak.

Before applying, establish:

- a public repository and public maintainer profile;
- Apache-2.0 license and clear attribution;
- working code and tagged releases;
- external issues, reviews, or contributors;
- recurring PR review, issue triage, security, and release activity;
- a short explanation of why the profile matters beyond Candao;
- actual usage signals such as integrations, dependent projects, downloads, pilots, or conformance implementations.

Do not optimize for fake stars or inflated activity. Apply when the project is demonstrably active; the program explicitly allows applications based on ecosystem importance even when a project does not neatly fit every criterion.
